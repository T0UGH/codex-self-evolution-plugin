## 三条主线状态

### Stable Memory

现状：

- `SessionStart` 会读取当前 repo bucket 的 `USER.md` / `MEMORY.md`
- 空文件会注入 `_No entries yet._`
- memory 和 recall contract 一起进入 `additionalContext`

问题：

- 当前直接拼完整 `USER.md` / `MEMORY.md`，memory 长大后会挤占上下文预算
- `USER.md` 位于 repo bucket 内，名字像全局用户记忆，但实际行为是 per-repo，概念上容易混淆
- 父进程只校验写入路径和 hash，没有校验 memory 内容是否包含运行元数据或 transient 信息

本轮讨论后的方向：

- 取消 `USER.md` / `MEMORY.md` 双文件模型，收敛到唯一有效的 `MEMORY.md`
- 旧 `USER.md` 如果存在，保留在磁盘上，但新版本不读取、不写入、不迁移、不删除
- `MEMORY.md` 使用纯 Markdown，推荐章节但不强制，不要求 YAML / JSON schema
- `SessionStart` 永远全文注入 `MEMORY.md`，不截断、不过滤、不因 lint / secret / size hard block
- `memory/refs/` 作为固定二级引用区，不默认注入；主 `MEMORY.md` 只保留一句摘要和绝对路径
- 后台 review agent 直接维护 `MEMORY.md` / `refs/`，可以删除无价值内容，也可以把有价值但占地方的内容下沉到 `refs/`
- Memory 层只记录时间标记，不负责自动过期；是否刷新、替换、删除交给 review agent
- parent validation 保持轻量，只校验 receipt、job id 和路径边界；失败只标记，不回滚、不阻断

建议实现：

- 移除 `USER.md` 读取和写入路径
- `SessionStart` 改为只读取并全文注入 `MEMORY.md`
- 新增 `memory/refs/` 目录并允许 review agent 维护
- 更新 reflection prompt：memory 维护目标是纯 Markdown 热上下文，而不是结构化 schema
- `csep status` 可以提示 legacy `USER.md`、memory size、lint / secret warning，但不改变注入行为

### Session Recall

现状：

- Stop hook 和 backfill 都写入 SQLite/FTS
- `csep recall bootstrap` 已作为正式入口发布
- backfill 已按 transcript mtime 新到旧导入
- status 能检测历史 transcript 数量并给出 bootstrap 建议

问题：

- 本机已安装 tool 仍是 `1.0.0`，真实 hook 暂时还跑旧代码
- `csep recall` 查不到时，还不会基于 DB / `~/.codex/sessions` 状态给自救提示
- Stop hook 缺 `transcript_path` 时只记录错误，没有尝试按 session id / mtime 兜底定位 transcript
- 搜索排序仍主要依赖 FTS5 + 简单 role 权重

本轮讨论后的方向：

- Recall 是本地历史证据检索，不是问答工具，也不使用 LLM summary
- 使用心智改为 `rg over past sessions`：搜索短 needle，不搜索长自然语言问题
- Recall 使用说明作为 CSEP 插件自带 skill 暴露给 Codex harness，不再通过 `SessionStart` 注入完整 contract
- CLI 也配合 grep-like 心智：支持 `|` OR alias，普通多 token query 可 strict -> OR fallback
- 默认输出 session-level extractive evidence window，不做重 UI、不做 embedding
- 每个 session 默认展示 2 个 evidence window，可用 `--windows-per-session` 调整
- 默认 evidence window 优先 `user` / `assistant` / `tool`，`developer` / `system` 可索引但不优先展示
- `no_match` 保持简单，不输出统计、不输出 bootstrap / docs / MEMORY 模板建议
- CLI 不自动 repo -> global fallback；需要跨 repo 时由 agent 显式加 `--global`
- 实施计划已落到 `docs/implementation-plans/2026-05-16-session-recall-implementation-plan.md`
- 实现已完成：plugin skill、SessionStart 短提示、grep-like query、session evidence windows、developer/system 降噪、recent preview 修正
- 真实搜索质量验证已记录到 `docs/recall-search-quality-2026-05-16.md`

建议：

- 增加 `csep --version`，并让 `csep status` 显示 installed/source/PyPI 版本差异
- 为 Stop hook 增加 transcript discovery fallback
- 新增插件 skill：`skills/csep-session-recall/SKILL.md`
- 插件 manifest 增加 `"skills": "./skills/"`，并保持 source bundle / marketplace bundle 一致
- `csep recall` 支持 `|` OR alias、strict -> OR fallback、`--all-terms`
- 搜索排序加入 recency、repo/worktree 精确度、同 session 多 hit、role 权重和工具名权重
- 参考 Hermes 后续补 CJK / trigram / LIKE fallback，但不引入 LLM

### Reflection Skills

现状：

- trigger policy 根据 stop 次数、可读文本、工具调用和高信号关键词决定是否排队
- reflection worker fork child Codex
- child 只允许写 memory 和 `csep-reflect-*` skill
- parent 校验 receipt、路径、hash、skill frontmatter 和必需章节

问题：

- `build_reflection_prompt()` 接收 `review_memory` / `review_skills`，但当前 prompt 仍固定要求 review memory and skills
- trigger 一旦 queued，`review_memory` 和 `review_skills` 都为 true，没有区分 memory-only / skill-only
- active skill 只有结构校验，没有重复检测、替代关系或实际加载验证
- 默认 `one_shot_active` 可以保持简单，但需要更好的边界约束，避免生成不该进入 skill 的内容

本轮讨论后的方向：

- Reflection Skills 只承接反复出现、可复用、步骤明确的工作流
- 一次性任务结论、具体状态、项目事实、用户偏好、未跑通临时方案不进入 skill
- reflection 必须 scope-aware：memory 触发只审 memory，skill 触发才审 skill；两者同时触发时才一起审
- prompt、trigger、receipt validation 都要遵守 `review_memory` / `review_skills`
- 短期不优先引入复杂发布门槛，skill 机制尽量保持简单
- 一个合格的 `csep-reflect-*` `SKILL.md` 仍可直接 active
- `one_shot_active` 可以继续作为简单默认，但必须配合 scope-aware prompt、严格结构校验和边界校验
- 发布前做重复和冲突检测，避免同类 workflow 反复生成多个 skill
- `evidence` / `draft` / lifecycle metadata 作为后续可选增强，不作为这一轮优先项

建议：

- 让 reflection prompt 真实遵守 `review_memory` / `review_skills`
- trigger 按触发原因生成 scope-aware decision
- 保留简单 active skill 模型，先补重复/冲突检测和 activation/load 验证
- 加强 receipt validation：当 `review_skills=false` 时不允许新增或修改 skill
- 将 evidence-first / draft lifecycle / `.csep-skill.json` metadata 留作后续可选增强
