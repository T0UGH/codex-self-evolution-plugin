Codex Self Evolution 当前架构

当前实现只保留 session 级闭环：Memory、Skill、Session Recall 三条线都从 Codex lifecycle hooks 产生，并在下一次会话被消费。

生命周期总览

SessionStart读取 repo bucket
注入背景USER.md / MEMORY.md
Codex 工作普通对话与工具调用
Stop归档 transcript
Trigger Policysession 级计数器 + 高信号关键词
Reflection Childapp-server fork 当前 thread
下次消费memory / skill / recall 生效

三条数据线

Memory

怎么产生
Stop hook 达到 memory nudge 条件后，reflection child 写入 repo bucket 下的 memory/USER.md 和 memory/MEMORY.md。
怎么校验
child 必须写 receipt.json；parent 只承认 receipt 中声明且位于允许目录内的写入。
怎么消费
下一次 SessionStart 读取同一 repo bucket，并把 stable background 注入 Codex。

Skill

怎么产生
Stop hook 达到 skill nudge 条件后，同一个 reflection child 可以一次性产出 active skill。
写到哪里
只允许写入 ~/.codex/skills/csep-reflect-*；前缀和路径由 parent 校验。
怎么消费
Codex 原生 skills loader 在后续会话中按 description 触发。

Session Recall

怎么产生
Stop hook 默认把 Codex transcript 归档到 session_recall/state.db，并建立 FTS 索引。
如何分组
默认按当前 repo scope 检索；同一个 git common dir 下的多个 worktree 视为同一个 repo。
怎么消费
模型或用户显式调用 csep recall、csep recall --recent、csep recall --global。

关键状态与命令

对象路径 / 命令作用
Plugin hooks plugins/codex-self-evolution/.codex-plugin/hooks.json 声明 session-start --from-stdin 和 session-stop --from-stdin。
Reflection state ~/.codex-self-evolution/session_reflection/ 保存 job、trigger state、child thread 映射、receipt 和 validation。
Repo memory ~/.codex-self-evolution/projects/<bucket>/memory/ 保存下一次 SessionStart 注入的稳定背景。
Reflect skills ~/.codex/skills/csep-reflect-* 保存 reflection child 产出的可复用流程。
Recall store ~/.codex-self-evolution/session_recall/state.db 保存原始 session 消息、repo 元数据和 FTS 索引。
Status codex-self-evolution status 只读检查 plugin hooks、session reflection、session recall、环境文件和本地工具。

触发规则是 session 级别的增量窗口，不是全局计数；同一父 session 的活跃 job 会阻止递归 fork。
